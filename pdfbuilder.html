Stage 2 · AI parsing

GPT-4o-mini structures messy OCR into clean JSON

The raw OCR text — typos, line breaks, merged tokens and all — is sent to GPT-4o-mini with a precision prompt. It returns a validated JSON array of { name, address } objects, filling gaps with placeholder tags rather than silently dropping records.

GPT-4o-mini JSON mode Graceful fallback
~180ms AI parse
Stage 4 · Document output

Premium A4 PDF — print-ready, branded, configurable

pdfkit renders an HTML template with a blue accent card system, executive summary box, and configurable layout — compact 2-column or standard single-column. Text alignment, sort order, and deduplication are all API parameters.

pdfkit A4 · Letter Compact mode Page-break aware
~220ms render
Stage 3 · Data pipeline

Sorting, deduplication, and layout control — server-side

Every record set passes through a shared cleaning layer before any file is rendered. Deduplication uses a case-normalised tuple key on (name, address) — catching duplicates even if capitalization differs. Sorting runs A→Z or Z→A on the cleaned name field. All three operations are optional and toggled per request.

Sort order?sort_order=asc | desc
Deduplication?remove_duplicates=true
Card layout?compact_mode=true | false
Text alignment?text_alignment=left | center | right | justify
O(n) dedup Stable sort 4 layout params

Reliability

Structured errors, graceful fallbacks, zero silent failures

Every failure path raises a typed HTTP exception with a clear detail message. If OCR finds no text, a 400 is returned immediately. If the AI key is absent, the pipeline falls back to a line-pair parser — you always get a document, never a silent empty file.

200 Success 400 Bad input 500 Pipeline error
HTTPException OCR fallback No silent errors
Input formats

Any image format PIL supports — JPEG, PNG, TIFF, WEBP

The UploadFile handler accepts any PIL-compatible image. The bytes are opened directly in memory — no temp file writes, no disk I/O overhead. Multi-page TIFF and multi-frame images are handled by Tesseract's native page segmentation.

JPEG · PNG TIFF · WEBP In-memory No disk write

How it works

Four stages,
one clean document.

Every call to /analyze-photo-to-pdf travels the same deterministic pipeline. If the AI key is missing at stage 2, a line-pair fallback kicks in automatically — so you never get an empty response.

1

Upload & OCR

PIL opens the image from memory. Tesseract v5 LSTM extracts all readable text, returning a raw string regardless of layout complexity.

pytesseract · PIL
2

AI structuring

GPT-4o-mini receives a precision prompt with the OCR text and returns a validated JSON array of { name, address } objects — typos corrected.

gpt-4o-mini · JSON mode
3

Clean & sort

Records pass through the shared pipeline layer: deduplication by normalised key, optional A→Z or Z→A sort, and Pydantic validation of each field.

process_data_cleaning()
4

Render & return

pdfkit renders the branded HTML template to an A4 PDF. The filename and metadata are returned in the JSON response body.

pdfkit · wkhtmltopdf

API reference

Two endpoints.
Full pipeline.

Both accept multipart form data or JSON. Both return structured JSON with the output filename. Base URL: https://api.docintel.io/v1

POST
/analyze-photo-to-pdf
Flagship endpoint. Accepts a photo, runs the full OCR → AI → clean → PDF pipeline, and returns the output filename plus metadata.
Parameters (multipart/form-data)
file UploadFile Image file. JPEG, PNG, TIFF, WEBP, or any PIL-compatible format.
topic string Document subject label shown in the PDF header and used in the AI prompt context.
compact_mode bool When true, switches to a two-column card layout to fit more records per page.
text_alignment string Card text alignment: left (default) · center · right · justify
Response 200
"status": "success",
"records_extracted_count": 24,
"ocr_text_discovered": "J0hn Sm1th...",
"pdf_file": "ocr_processed_report.pdf"
POST
/generate-premium-pdf
Direct PDF generation from pre-structured data. Use when records are already clean and you only need a formatted document.
Body (application/json — DataPayload)
topic string Document subject label for the PDF header.
records Record[] Array of { name?, address? } objects. Both fields optional.
sort_order string? Sort before rendering: "asc" or "desc". Omit to preserve input order.
remove_duplicates bool Deduplicate records by (name, address) tuple before rendering.
compact_mode bool Two-column card layout for high-density output.
Response 200
"status": "success",
"file": "ocr_processed_report.pdf"

Pydantic schemas

Two models. Fully validated.

All request bodies are validated at the framework layer by Pydantic v2. Both fields in Record are optional — the rendering layer substitutes safe fallbacks so malformed data never crashes the pipeline.
